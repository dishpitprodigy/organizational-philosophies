# Appendix C: Talent Development Workbook

*Part Appendices*

The four instruments form one loop: personal context becomes competency calibration, calibration becomes a real-work development plan, and the resulting evidence feeds the next decision.

## TDA Personal Development Plan

This template is the employee-facing entry point into Talent Development Architecture. It gives the employee and manager one clean place to discuss role context, career direction, preferences, constraints, demonstrated strengths, development needs, and the work that should become the person's next safe reps.

The purpose is not to produce a polished career narrative. The purpose is to create a shared operating picture.

### Use

1. The employee completes the first draft.
2. The manager adds calibration notes, organizational context, and missing evidence.
3. The employee and manager review it in a one-on-one.
4. The agreed development targets move into the TDA 70-20-10 Development Plan.
5. The plan is reviewed at least quarterly, and after major stretch assignments, role changes, or performance regressions.

## TDA Competency Calibration

This template turns competency language into evidence. It is not a personality assessment and it is not a performance rating. It is a shared calibration tool for answering one question:

What can this person currently demonstrate, what does the next operating mode require, and what safe reps would close the gap?

### Use

1. Select the current role, target role, target scope, or next operating mode.
2. Identify the competencies that actually matter for that target.
3. Define each competency in observable behavior.
4. The employee completes a self assessment with evidence.
5. The manager completes calibration with evidence.
6. The employee and manager discuss the difference between the two interpretations.
7. Confirm development targets and move them into a 70-20-10 plan.

### Proficiency Stages

Use stages that describe observable work. Rename them if the organization already has a level model, but keep the evidence discipline.

| Stage | Meaning | Evidence Pattern |
|---|---|---|
| Awareness | Understands the concept and can recognize it in context. | Can explain the idea, identify examples, and ask useful questions. |
| Guided execution | Can perform the work with support, review, or close supervision. | Completes bounded tasks when expectations, examples, and review are available. |
| Independent execution | Can perform the work reliably inside normal scope. | Delivers the work without unusual support and handles routine tradeoffs. |
| Broader coordination | Can coordinate the work across people, systems, or teams. | Anticipates dependencies, negotiates tradeoffs, and helps others execute. |
| System ownership | Can improve the operating system around the work. | Changes standards, processes, tooling, or strategy in ways that create leverage beyond direct execution. |

## TDA 70-20-10 Development Plan

This template translates development needs into work. The ratio is not accounting. It is a design principle:

- 70 percent: real work, stretch assignments, shadowing, projects, process improvement, ownership reps, and other experience-based learning.
- 20 percent: coaching, mentoring, peer feedback, communities of practice, reviews, and learning from people who already perform the capability well.
- 10 percent: formal training, courses, reading, labs, certifications, reference material, or structured study.

The important rule is this: training is not evidence of readiness. Training supports readiness. Evidence comes from observed behavior under realistic conditions.

### Use

1. Start from a Personal Development Plan or Competency Calibration.
2. Choose one to three development objectives.
3. Define real work reps first.
4. Add feedback sources.
5. Add formal support.
6. Define risk boundaries and evidence.
7. Review progress at least quarterly.

### 70 Percent: Learning Through Real Work

Choose work that creates legitimate reps without hiding risk or turning development into unsupervised production work.

Possible real-work reps:

- complete a bounded stretch assignment
- shadow a higher-risk workflow, then own a read-only step
- own a reversible change under review
- join a project team with clear scope
- lead a small process improvement
- document a recurring problem, then improve the workflow
- teach another person a task to test understanding
- present a technical or operational finding to the team
- support another team for a defined time box
- run a post-incident improvement item
- build a runbook, checklist, test, automation, or standard work artifact

## TDA Performance Evidence Ledger

This template prevents annual review from becoming memory reconstruction. It connects accountabilities, measures, changed conditions, development actions, employee reflection, manager observation, and next decisions into one evidence record.

The ledger is not a surveillance file. It is a reconciliation tool. It should preserve useful evidence without turning every developmental conversation into a disciplinary artifact.

### Use

1. Define accountabilities and expected evidence early.
2. Update the ledger when meaningful work, feedback, scope changes, or development reps occur.
3. Label evidence types.
4. Reconcile evidence at mid-cycle and end-cycle.
5. Feed the result into the next Personal Development Plan, 70-20-10 plan, assignment decision, promotion decision, or support change.

### Evidence Labels

| Label | Meaning |
|---|---|
| Observed behavior | Something directly seen in work, meetings, incidents, artifacts, delivery, or collaboration. |
| Outcome measure | A metric, target, service level, completion record, quality result, or other measured result. |
| Work artifact | A runbook, document, design, automation, ticket, test, project output, or other created object. |
| Self report | The employee's account of what happened, what they intended, or what they learned. |
| Manager interpretation | The manager's read on what the evidence means. |
| Peer or stakeholder input | Feedback from someone affected by, or close to, the work. |
| Assumption | A claim that still needs confirmation. |
